### OS: malloc(32 KiB) trace — first pass
- Got: libc serves from arena or calls brk; MOV -> walk -> #PF, CR2 = faulting address; kernel fills PTE; instruction re-runs.
- WRONG: "arena (the stack assigned to the process)" — arena = malloc's heap region (main arena grows via brk), not the stack.
- Missing: 128 KiB mmap threshold (why brk here, not mmap); brk only extends the heap VMA, no frames; overcommit.
- Missing: what the fault handler checks = the VMA (inside a VMA with write permission -> allocate a ZEROED frame; no VMA -> SIGSEGV). "sees it is not assigned" conflates VMA and PTE.
- Missing: chunk header written by malloc just below the pointer -> first page may already be present, the int write may not fault. TLB fill not mentioned.
- Missing: exit (VMAs torn down, frames + page tables freed).
- Probe 1 (arena): recovered — "heap of the process, called the arena". OK. Precise: glibc's main arena = brk heap; other threads' arenas = mmap'd heaps.
- Probe 2 (fault check): "a struct for all the RAM addresses, what has been written where and with which permission" — vague and partly wrong: it's per-process mm_struct -> VMAs (vm_area_struct: range, perms, backing), virtual not physical, nothing about "what has been written". Never named VMA.
- Probe 3: KEY MISCONCEPTION — "one global table for the whole RAM, describes both physical and VA; brk assigns physical addresses to the process". Wrong on all three: VMAs are per-process + virtual; struct page array is the global physical one; brk only moves mm->brk / extends the heap VMA, no frames. Corrected in-round. This was in the OS 2 review sheet (Mon 26) -> revisit os1_os2_review.md tonight.
- Probe 4 (does the int write fault?): "malloc almost never faults, so probably not" — right verdict, wrong reason (mixed up "rarely returns NULL" with "rarely faults"). Real reason: malloc writes the chunk header just below the pointer -> that write takes the fault, the page is present when your int lands (same page unless at a page boundary).
- Probe 5 (exit): "page tables, mm_structs gone; frames interpreted as free since the process doesn't exist" — WRONG model (no lazy reclaim by owner lookup). exit_mmap walks VMAs/PTEs, drops each page's refcount/mapcount, a frame returns to buddy free lists when refcount hits 0 (shared libc text / page cache stays), page tables freed, TLB flushed, mm freed when mm_users -> 0.
### OS: "inside a guest" follow-up
- Got: two-stage translation, every guest walk also translated through host tables (2D walk). Good.
- Vague: "two set of pages" -> should be: guest page tables (GVA->GPA, owned by guest) + EPT (GPA->HPA, owned by KVM).
- Missing so far: guest #PF is handled by the GUEST kernel, no VM exit (with EPT); unbacked GPA -> EPT violation -> VM exit -> KVM.
- Q1 right: guest kernel handles its own #PF via its own mm/VMAs, no VM exit. Good.
- Term error: "VMM owns the shadow pages" — shadow page tables are the pre-EPT software scheme (KVM builds GVA->HPA, traps guest PT writes). With EPT: guest owns guest PTs (GVA->GPA); KVM (host kernel) owns EPT (GPA->HPA); userspace VMM owns the HVA mapping of guest RAM, registered as memslots (GPA->HVA).
